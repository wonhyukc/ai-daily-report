# Audit to Issues — 코드베이스 점검 후 GitHub 이슈 등록

## Overview

코드베이스를 점검해 버그·개선점을 찾고, **근본 원인별로 묶어** GitHub 이슈로 등록하는 전체 파이프라인. 핵심 원칙: **중복 대조 없이 등록하지 않고, 발견 1건 = 이슈 1개로 기계적으로 만들지 않는다.**

인자: `$ARGUMENTS` (점검 범위 제한 또는 제외할 기존 이슈)

## 단계별 체크리스트 (TodoWrite로 추적)

### 1단계: 사전 확인 (Pre-flight)

- [ ] `git remote -v` — 올바른 저장소인지 확인 (포크/업스트림 혼동 방지)
- [ ] `gh issue list --state all --limit 100` — **기존 이슈 전수 조회.** 신규 발견은 반드시 이 목록과 대조 후에만 후보로 채택
- [ ] 이전 점검 리포트 확인: `.claude/health-reports/` — 있으면 읽고 이미 이슈화된 항목 제외

### 2단계: 점검 (Audit)

- [ ] 루브릭 채점 리포트 확인: `.claude/health-reports/*-rubric.md` 최신 파일 — 있으면 **감점 항목을 점검 후보의 출발점**으로 사용 (quality-rubric 스킬이 생성). 없거나 오래됐으면(7일+) quality-rubric을 먼저 실행하는 것을 권장

소스가 ~1,000줄 이하면 전부 직접 읽는다. 크면 Explore 서브에이전트로 영역별 병렬 분석.

점검 관점 (5개 카테고리, A~F 등급):
| 카테고리 | 확인 내용 |
|---------|----------|
| 보안 | 하드코딩 시크릿, .gitignore 누락, 의존성 감사 |
| 타입 안전성 | 타입체커 에러, deprecated API, 타입 소실 구간 |
| 데드코드 | 미사용 의존성·설정·export, 오래된 TODO |
| 문서 동기화 | README 기능 표시 vs 실제 구현, 수치·경로 불일치 |
| 코드 품질 | 테스트 유무, 데이터 유실 가능 설계, 오탐 로직, 크래시 edge case |

- 정적 도구(mypy, pip-audit 등)는 가능하면 실행하고, **실행 불가 환경이면 리포트에 명시** (가능한 척 금지)
- 발견마다 `파일:라인` 근거와 심각도(Critical/High/Medium/Low)를 기록

### 3단계: 리포트 저장

- [ ] `.claude/health-reports/YYYY-MM-DD.md`에 전체 결과 저장 (종합 등급표 + 심각도별 목록)
- [ ] 저장 전 `.gitignore`에 `.claude/health-reports/` 포함 여부 확인, 없으면 추가 (리포트는 커밋 금지)

### 4단계: 사용자 확인 (관문)

**이슈 등록은 외부 공개 행위다.** 원래 요청에 "이슈로 등록까지"가 명시돼 있지 않으면, 발견 요약을 보고하고 등록 승인을 받은 후 진행한다. 명시돼 있으면 바로 진행.

### 5단계: 이슈 등록

- [ ] `gh label list` — **실제 존재하는 라벨 확인 후** `--label` 사용 (없는 라벨 지정 시 생성 실패). 본문에 "Labels: bug"라고 텍스트로만 쓰는 것은 라벨이 아님
- [ ] **근본 원인별 그룹핑**: 같은 원인에서 파생된 발견은 1개 이슈로 (예: 캐시 저장 시점 결함 → DRY_RUN 오염 + 실패 시 유실 = 이슈 1개). Low 항목은 성격별(기술부채/문서/테스트) 통합
- [ ] 우선순위(High→Low) 순서로 생성 — 이슈 번호가 곧 우선순위가 되도록
- [ ] 본문 컨벤션: `## Problem` / `## Proposed Solution` / `## Files Affected` / `## Severity` + 출처(리포트 경로). 기존 이슈 스타일이 있으면 그것을 따름
- [ ] 기존 이슈 범위에 속하는 신규 발견은 새 이슈 대신 `gh issue comment`로 보강

### 6단계: 마무리 보고

- 등록 결과 표 (번호·제목·라벨·심각도, 링크 포함)
- **이슈 간 의존 관계와 권장 작업 순서** (예: 테스트 인프라가 TDD 수정의 전제, 같은 파일 수정 이슈는 순차 처리)

## Common Mistakes

| 실수 | 방지책 |
|------|--------|
| 기존 이슈와 중복 등록 | 1단계 전수 조회를 건너뛰지 말 것 — 이전 점검이 이미 이슈화했을 수 있음 |
| 발견 19건 → 이슈 19개 | 근본 원인별 그룹핑. 보통 발견 수의 50~60%로 줄어듦 |
| 존재하지 않는 라벨로 생성 실패 | `gh label list` 선행. 기본 라벨은 bug/enhancement/documentation 정도 |
| 점검만 요청받았는데 이슈까지 등록 | 4단계 관문 — 등록은 명시 요청 또는 승인 후에만 |
| 리포트 미저장 | 다음 점검의 중복 대조 기준이 사라짐. 반드시 저장 |
| 도구 미실행을 숨김 | venv 없음 등 제약은 리포트 상단에 명시 |
