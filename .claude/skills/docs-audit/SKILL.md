# 📋 문서 감사 & 최적화 스킬 (Docs Audit)

프로젝트의 **현재 상태만** 정확히 표현하는 문서를 만듭니다.

## 🎯 목표

```
❌ 과거 히스토리  →  ✅ 현재 상태
❌ 중복 내용      →  ✅ 단일 진실 공급원
❌ 과정/과정      →  ✅ 결과 (결정)
❌ 모호함         →  ✅ 명확함
```

## 📖 핵심 원칙

### 1. 현재 상태만 표현
- **과거 변경**: git log에 위임 (커밋 메시지로 충분)
- **과정**: 코드와 주석에 위임
- **히스토리**: 필요하면 `git log --oneline`으로 확인

### 2. 문서의 양 최소화
- **중복 제거**: 같은 정보가 여러 곳에 없어야 함
- **불필요한 메타**: "최종 업데이트" 날짜 같은 것 제거
- **콘텐츠 분리**: README ≠ CLAUDE.md ≠ 코드 주석

### 3. 역할별 문서 구분
| 문서 | 대상 | 내용 |
|------|------|------|
| **README.md** | 사용자 | 설치, 실행, 현재 기능, 상태 |
| **CLAUDE.md** | 개발자 | 개발 규칙, 아키텍처, 체크리스트 |
| **코드 주석** | 구현자 | 이슈 참조, 설계 결정 이유 |
| **git log** | 탐구자 | 과거 변경, 버그 수정 이력 |

## 🔍 점검 프로세스

### 단계 1: 현황 파악 (Read Phase)
```bash
# 코드 상태 확인
git log --oneline -10          # 최근 커밋
git status                      # 워킹 트리
./venv/bin/pytest -q           # 테스트

# GitHub 상태 확인
gh issue list --state open      # 열린 이슈
gh pr list --state open         # 열린 PR
```

**기록할 정보:**
- Phase (완료/진행/예정)
- 테스트 (통과/실패 개수)
- 이슈 (열림/닫힘 개수)
- PR (열림/닫힘 개수)

### 단계 2: 문서 분석 (Analyze Phase)
```
README.md
├─ 현황 O  (살리기)
├─ 기능 O  (살리기)
├─ 설정 O  (살리기)
└─ "최근 버그 수정" 섹션 ❌ (git log와 중복)

CLAUDE.md
├─ 개발 규칙 O  (살리기)
├─ 체크리스트 O (살리기)
└─ "과거 설계 결정" 섹션 ❌ (코드 주석과 중복)
```

**체크할 것:**
- [ ] 히스토리/과정 섹션이 있는가?
- [ ] 날짜/메타정보가 필요한가?
- [ ] 같은 정보가 여러 곳에 있는가?
- [ ] git/코드로 충분한 내용을 문서에 복제했는가?

### 단계 3: 정리 (Clean Phase)

**제거 대상:**
```
❌ "최근 13개 버그 수정" (git log: 커밋 #1~#13)
❌ "Phase 1에서 적용된 설계" (코드 주석: Issue #N 참조)
❌ "최종 업데이트: 2026-06-11" (코드가 현재면 자동 최신)
❌ 같은 설명이 README + CLAUDE에 있는 경우 하나만 유지
```

**유지 대상:**
```
✅ 현재 Phase (1 완료, 다음 단계)
✅ 테스트 상태 (60/60 통과)
✅ 열린 이슈/PR 개수 (0개)
✅ 개발자 규칙 (Red-Green-Refactor, 타입, 테스트)
✅ 코드 주석 (Issue #N 참조)
```

### 단계 4: 정량화 (Measure Phase)

**문서화 전:**
```
README:  339줄
CLAUDE:  219줄
총합:    558줄
```

**문서화 후:**
```
README:  309줄  (-30줄)
CLAUDE:  131줄  (-88줄)
총합:    440줄  (-118줄, 21% 감소)
```

**검증:**
- [ ] 라인 수 감소했는가?
- [ ] 중복 제거했는가?
- [ ] 테스트 여전히 통과하는가?
- [ ] 새 정보 손실 없는가?

### 단계 5: 커밋 (Commit Phase)

```bash
git add README.md CLAUDE.md
git commit -m "docs: 문서 최적화 — 현재 상태만 표현, 히스토리 제거

README.md
- 🔧 '버그 수정' 섹션 제거 (git log로 충분)
- 현재 상태 테이블만 유지

CLAUDE.md
- 📚 '설계 결정' 섹션 제거 (코드 주석으로 충분)
- 현재 개발 규칙만 유지

결과: 118줄 감소 (558 → 440), 중복 제거

원칙
✅ 현재 상태만 (과거 제거)
✅ 최소 문서량 (중복 제거)
✅ 명확한 역할 (README/CLAUDE/코드 분리)
"
