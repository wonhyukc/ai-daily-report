# 📋 Docs Audit 스킬 — 사용 가이드

문서가 프로젝트의 **현재 상태만** 정확히 반영하도록 점검하고 최적화합니다.

## 언제 사용하나?

프로젝트가 이런 상태일 때 이 스킬을 호출합니다:

```
✅ 코드 구현은 완료됨
✅ 테스트 통과
❓ 문서가 현황을 정확히 반영하는가?
```

### 트리거 예시

사용자가 이런 요청을 하면 이 스킬이 자동으로 활성화됩니다:

- "문서 상태를 점검해줘"
- "현황을 정확하게 문서화해줘"
- "문서에서 중복을 제거해줘"
- "문서 정확도를 확인해줘"
- "README와 CLAUDE.md가 겹치는 부분을 정리해줘"

## 사용 방법

### 1️⃣ 스킬 호출
```
사용자: "현황 문서화 점검해줘"
Claude: "이 스킬을 사용하겠습니다"
```

### 2️⃣ 자동으로 수행되는 작업
- 현재 코드 상태 분석 (git, 테스트, 이슈)
- 문서 검토 (README, CLAUDE.md, 코드 주석)
- 중복 식별
- 히스토리/불필요 내용 식별

### 3️⃣ 결과
```
점검 결과:
- ✅ 코드: 완벽
- ⚠️ 문서: 부분적 (중복 있음, 히스토리 포함)

개선 사항:
- README의 "버그 수정" 섹션 제거
- CLAUDE의 "설계 결정" 섹션 제거
- 라인 수: 558 → 440 (21% 감소)
```

### 4️⃣ 자동 커밋
문서가 정리되면 자동으로 커밋됩니다.

## 핵심 개념

### "현재 상태"란?

```
✅ 포함: 지금 이 순간의 프로젝트 상태
  - Phase (1 완료, 다음 단계)
  - 테스트 (60/60 통과)
  - 이슈 (0개 열림)
  - 개발 규칙 (지금 지켜야 할 것)

❌ 제외: 과거 또는 외부
  - "최근에 고쳤던 13개 버그" → git log에 있음
  - "이전 설계 결정" → 코드 주석에 있음
  - "최종 업데이트 2026-06-11" → 히스토리
```

### "최소화"란?

```
❌ 같은 정보 3곳에 있음
README    "ProcessedItem은 NewsItem을 확장"
CLAUDE    "ProcessedItem은 NewsItem을 확장"
코드 주석 "ProcessedItem은 NewsItem을 확장"

✅ 한곳에만 있음
CLAUDE: "ProcessedItem은 NewsItem을 확장"
코드 주석: "Issue #11 참조"
```

### "역할 분리"란?

```
README.md
→ 사용자 입장 (설치, 실행, 기능)
→ "이 프로젝트가 뭐하는 건가?"

CLAUDE.md
→ 개발자 입장 (규칙, 패턴, 체크리스트)
→ "어떻게 개발할 건가?"

코드 주석
→ 구현자 입장 (이슈, 결정, 근거)
→ "왜 이렇게 구현했나?"

git log
→ 탐구자 입장 (역사, 변경, 이유)
→ "지난번에 뭘 고쳤나?"
```

## FAQ

### Q: 과거를 알아야 하면?
**A**: `git log` 또는 `git blame`으로 확인하세요.
```bash
git log --grep="버그" --oneline    # 특정 주제의 커밋
git blame src/file.py              # 왜 이렇게 됐는지
```

### Q: 설계 결정이 중요하면?
**A**: 코드에 주석으로 남기세요.
```python
# Issue #11: ProcessedItem으로 파이프라인 전체에서 타입 유지
class ProcessedItem(NewsItem):
    ...
```

### Q: 문서 버전 관리는?
**A**: git이 관리합니다. 문서에 날짜를 쓸 필요 없습니다.
```
❌ "최종 업데이트: 2026-06-11"
✅ 코드 = 최신 문서
```

### Q: 새 팀원에게 과정을 설명하려면?
**A**: 
1. README: 현재 기능과 상태 설명
2. CLAUDE.md: 개발 규칙 설명
3. git log: "이전에 뭘 했는가" 설명
4. 코드: 구체적인 구현 확인
