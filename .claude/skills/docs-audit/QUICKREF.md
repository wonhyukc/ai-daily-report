# ⚡ Docs Audit 스킬 — 빠른 참고

## 한 줄 요약
**현재 상태만, 최소 양으로, 중복 없이** 문서화합니다.

---

## 3가지 핵심 원칙

### 1️⃣ 현재 상태만 표현
```
❌ 제거
- "최근 13개 버그 고쳤습니다" (git log에 있음)
- "Phase 1 설계 결정" (코드 주석에 있음)
- "최종 업데이트: 2026-06-11" (코드 = 최신)

✅ 유지
- "Phase 1 완료" (현재 상태)
- "테스트 60/60" (현재 상태)
- "개발 규칙: Red-Green-Refactor" (현재 규칙)
```

### 2️⃣ 문서 양 최소화
```
최소화 전: 558줄
   README  339줄
   CLAUDE  219줄

최소화 후: 440줄 (-118줄, 21% 감소)
   README  309줄
   CLAUDE  131줄
```

### 3️⃣ 중복 제거 & 역할 분리
```
README.md    → "사용자용" (설치, 실행, 기능)
CLAUDE.md    → "개발자용" (규칙, 패턴, 체크리스트)
코드 주석    → "구현용" (Issue #N 참조)
git log      → "탐구용" (변경 이력)

같은 내용이 두 곳에 있으면 안 됨!
```

## 5단계 프로세스

### ① Read (현황 파악)
```bash
git log --oneline -10
git status
./venv/bin/pytest -q
gh issue list --state open
```

### ② Analyze (문서 검토)
- [ ] 히스토리/과정 섹션 있는가?
- [ ] 날짜/메타정보 필요한가?
- [ ] 같은 정보가 여러 곳에 있는가?

### ③ Clean (정리)
```
README에서 제거:
  - "🔧 13개 버그 수정" 섹션 (27줄)

CLAUDE에서 제거:
  - "📚 설계 결정" 섹션 (88줄)

결과: 558줄 → 440줄
```

### ④ Measure (정량화)
```
변경 전: README 339줄 + CLAUDE 219줄 = 558줄
변경 후: README 309줄 + CLAUDE 131줄 = 440줄
감소율: 21.2%
```

### ⑤ Commit (커밋)
```bash
git commit -m "docs: 문서 최적화 — 현재 상태만 표현

README: 버그 수정 섹션 제거 (git log로 충분)
CLAUDE: 설계 결정 섹션 제거 (코드 주석으로 충분)

결과: 118줄 감소, 중복 제거, 현재 상태만 남김
"
```

## 사용 시기

```
프로젝트 진행 중:
  ❌ 아직 사용 안 함

Phase 완료 후:
  ✅ 이 스킬 사용
  ✅ 현황 문서화
  ✅ 문서 정확도 100%

다음 Phase 시작:
  ✅ 깔끔한 문서 상태
  ✅ 새 팀원도 이해하기 쉬움
```

## 문서 역할 분리

### README.md (사용자용)
```markdown
## 현재 상태
| Phase | 테스트 | 이슈 | PR |
| 1 완료 | 60/60 | 0개 | 0개 |

## 기능
- ✅ 수집
- ✅ 처리
- 🔄 요약 (Phase 2)

## 설치/실행/설정
...
```

### CLAUDE.md (개발자용)
```markdown
## 개발 규칙
- Red-Green-Refactor
- 타입 안정성
- 테스트 우선

## 체크리스트
- [ ] 테스트 작성
- [ ] 구현
- [ ] 통과
```

### 코드 주석 (구현용)
```python
# Issue #5: HackerNews URL 해시 충돌
# URL 없는 항목은 "source:title"로 대체
hash_source = item.url or f"{item.source}:{item.title}"
```

### git log (탐구용)
```
d6c458c fix: URL 없는 HackerNews 글의 dedup 해시 충돌 해결 (#5)
...
```

## 예시

### Before (부정확)
```
README: "최근 13개 버그를 고쳤습니다"
  - DateTime 통일
  - 이모지 인코딩
  - ... (너무 길어짐)

CLAUDE: "Phase 1에서 적용된 설계"
  - Dedup 안전성
  - Collector 강건성
  - ... (코드와 중복)

라인 수: 558줄
```

### After (정확)
```
README: "현재 Phase 1 완료, 테스트 60/60 통과"
  (버그 이력은 git log로 확인)

CLAUDE: "개발할 때 이 규칙을 따르세요"
  (과거 설계는 코드 주석으로 확인)

라인 수: 440줄
```

## FAQ

**Q: 과거를 알아야 하면?**
```bash
git log --oneline          # 무엇을 했는가
git blame src/file.py      # 왜 그렇게 했는가
git show commit-id         # 상세 정보
```

**Q: 문서가 오래되었으면?**
- 오래된 것이 아닙니다. 현재 코드 = 최신 문서입니다.
- 필요하면 `git log`에서 확인하세요.

**Q: 새 팀원을 위해?**
1. README: "이게 뭔가"
2. CLAUDE: "어떻게 개발하나"
3. `git log`: "지난번에 뭘 했나"
4. 코드: "구체적으로 어떻게"
