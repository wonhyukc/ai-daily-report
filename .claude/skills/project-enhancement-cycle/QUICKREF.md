# ⚡ Project Enhancement Cycle 스킬 — 빠른 참고

## 한 줄 요약
**감시 → 해결 → 정리의 순환을 반복하여 프로젝트 품질을 지속적으로 유지합니다.**

---

## 3가지 핵심 원칙

### 1️⃣ 자동 순환
```
❌ 일회성 점검
✅ 반복적 개선

audit-to-issues
     ↓
issues-plan-and-resolve
     ↓
docs-audit
     ↓
(새 이슈 있으면) → 다시 audit-to-issues로
(새 이슈 없으면) → 완료 ✅
```

### 2️⃣ 종료 조건 명확
```
조건: audit-to-issues 실행 후

새 이슈 등록됨?
  ├─ YES → 계속 순환
  └─ NO  → 사이클 종료 ✅
```

### 3️⃣ 안전 장치 포함
```
✅ 최대 사이클 수 제한 가능
✅ 각 단계마다 상태 확인
✅ 실패 시 중단 및 보고
✅ git 커밋으로 모든 변경사항 기록
```

## 5단계 프로세스

### Step 1️⃣: 감시
```bash
audit-to-issues 스킬 호출
  ↓
결과: 새 이슈 목록 수집

분기:
  - 이슈 있음 → Step 2로
  - 이슈 없음 → 완료 ✅
```

### Step 2️⃣: 해결 (이슈 있을 때만)
```bash
issues-plan-and-resolve 스킬 호출
  ↓
결과: 모든 이슈 해결

다음: Step 3으로
```

### Step 3️⃣: 정리
```bash
docs-audit 스킬 호출
  ↓
결과: 문서 최신화

다음: Step 4로
```

### Step 4️⃣: 재감시
```bash
audit-to-issues 스킬 재실행
  ↓
결과: 새 이슈 발견 여부 확인

분기:
  - 새 이슈 → Step 2로 (순환)
  - 이슈 없음 → 완료 ✅
```

## 사용 시나리오

### 📅 정기적 유지보수
```
매주 월요일:
  "프로젝트 개선 사이클"
  → 주간 버그 자동 발견 및 해결
  → 문서 최신화
```

### 🎯 Phase 완료 후
```
Phase 1 구현 완료:
  "프로젝트 개선 사이클"
  → 모든 버그 정리
  → 문서 완벽화
  → Phase 2 시작 준비
```

### 🔄 리팩토링 후
```
대규모 리팩토링 완료:
  "프로젝트 개선 사이클"
  → 리팩토링 버그 발견 및 해결
  → 코드 품질 검증
  → 문서 동기화
```

## 실행 시간 기준

```
사이클 1회:
  audit-to-issues:         5-10분
  issues-plan-and-resolve: 10-30분
  docs-audit:              2-5분
  ─────────────────────────
  Total:                   20-45분

예상 총 시간:
  3회 사이클: 60-135분
  (자동화로 실제는 더 짧음)
```

## 옵션

### 1️⃣ 최대 사이클 제한
```bash
"프로젝트 개선 사이클 (최대 3회)"
```
→ 무한 반복 방지

### 2️⃣ 특정 영역만
```bash
"프로젝트 개선 사이클 (보안만)"
"프로젝트 개선 사이클 (타입 체크만)"
```
→ 빠른 실행

### 3️⃣ 수동 검증
```bash
"프로젝트 개선 사이클 (수동 승인)"
```
→ 각 단계 전 승인

## 체크리스트

사이클 진행 중:

- [ ] audit-to-issues 실행됨?
- [ ] 이슈 발견되었는가?
- [ ] issues-plan-and-resolve 실행됨?
- [ ] 모든 이슈 해결되었는가?
- [ ] docs-audit 실행됨?
- [ ] 문서 정리 완료되었는가?
- [ ] 새 이슈 없어서 종료되었는가?

사이클 완료 후:

- [ ] 열린 이슈: 0개?
- [ ] 문서: 최신 상태?
- [ ] 테스트: 전부 통과?
- [ ] 커밋: 모두 생성됨?

## 문제 해결

### Q: 사이클이 끝나지 않으면?
```
→ 최대 사이클 제한 사용
→ "프로젝트 개선 사이클 (최대 3회)"
```

### Q: 자동 해결이 안 되는 이슈?
```
→ 수동으로 issues-plan-and-resolve에서 처리
→ 또는 "프로젝트 개선 사이클 (수동 승인)" 사용
```

### Q: 특정 스킬만 실행하고 싶으면?
```
/audit-to-issues
/issues-plan-and-resolve
/docs-audit
```
