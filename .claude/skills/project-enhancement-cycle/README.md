# 🔄 Project Enhancement Cycle 스킬 — 사용 가이드

프로젝트를 지속적으로 개선하는 자동화 워크플로우입니다. 코드베이스를 감시하고, 이슈를 해결하고, 문서를 정리하는 과정을 반복하여 프로젝트 품질을 유지합니다.

## 언제 사용하나?

프로젝트가 이런 상황일 때 이 스킬을 호출합니다:

```
✅ 코드 구현은 완료됨
✅ 테스트 통과
❓ 숨겨진 버그나 개선사항이 있을까?
❓ 문서가 현황을 정확히 반영하고 있을까?
```

### 트리거 예시

사용자가 이런 요청을 하면 이 스킬이 자동으로 활성화됩니다:

- "프로젝트 개선 사이클"
- "지속적 개선 해줘"
- "자동 점검 및 해결"
- "완전 점검 후 정리"
- "정기적 유지보수 해줘"

## 사용 방법

### 1️⃣ 스킬 호출
```
사용자: "프로젝트 개선 사이클"
Claude: "이 스킬을 사용하겠습니다"
```

### 2️⃣ 자동으로 수행되는 작업

스킬은 다음 순서로 자동 반복됩니다:

```
사이클 1:
  1️⃣ audit-to-issues
     └─ 코드베이스 감시 → 버그/개선사항 발견 → 이슈 등록
  
  2️⃣ issues-plan-and-resolve (이슈가 있으면)
     └─ 이슈 분석 → 자동 또는 반자동 해결 → 이슈 닫음
  
  3️⃣ docs-audit
     └─ 문서 점검 → 현황 반영 → 중복 제거 → 커밋
  
  🔄 audit-to-issues 재실행
     └─ 새 이슈 발견? → YES: 사이클 2 시작 / NO: 완료 ✅
```

### 3️⃣ 결과

```
점검 결과:
  ✅ 이슈 발견 & 해결: #1, #2, #3
  ✅ 문서 정리: 중복 제거, 현황 반영
  ✅ 커밋 자동 생성

사이클 진행:
  - Cycle 1: 5개 이슈 발견 & 해결
  - Cycle 2: 2개 이슈 발견 & 해결
  - Cycle 3: 0개 이슈 → 사이클 종료 ✅
```

## 핵심 개념

### "순환 (Cycle)"이란?

```
1회 순환 = 감시 → 해결 → 정리 → 재감시

✅ 포함: 자동으로 반복되는 개선 프로세스
  - 코드베이스 감시 (audit-to-issues)
  - 이슈 해결 (issues-plan-and-resolve)
  - 문서 정리 (docs-audit)

❌ 제외: 수동 개입 (필요시 사용자 승인)
  - 각 이슈 상세 검토는 사용자가 진행 가능
  - 자동 해결 불가 이슈는 수동 처리
```

### "종료 조건"이란?

```
audit-to-issues 실행 후:
  ✅ 새로운 이슈 등록됨
     → issues-plan-and-resolve로 진행
     → docs-audit으로 정리
     → 다시 audit-to-issues로 반복
  
  ✅ 이슈가 등록되지 않음
     → 사이클 종료 ✅
     → "프로젝트 개선 완료" 보고
```

### "안전 장치"란?

```
무한 루프 방지:
  - 최대 사이클 수 제한 가능
  - 각 단계마다 이슈 상태 확인
  - 실패 시 즉시 중단 및 보고
  
모든 변경사항 기록:
  - git 커밋으로 추적
  - 롤백 가능한 상태 유지
```

## 사용 시나리오

### 시나리오 1: 정기적 유지보수

```
매주 월요일 아침:
사용자: "프로젝트 개선 사이클"
↓
실행:
  ✅ 지난 주 버그 발견 및 해결
  ✅ 문서 최신화
  ✅ 코드 품질 점검
↓
결과:
  주간 건강도 점검 완료
  발견된 8개 이슈 해결
  문서 동기화
```

### 시나리오 2: Phase 완료 후 정리

```
Phase 1 구현 완료:
사용자: "프로젝트 개선 사이클"
↓
실행:
  ✅ Phase 1 구현 후 남은 버그 정리
  ✅ Phase 1 관련 모든 이슈 해결
  ✅ 문서 완벽화
↓
결과:
  Phase 2 시작 전 완전히 깨끗한 상태
  모든 이슈 해결됨
  문서 100% 정확
```

### 시나리오 3: 대규모 리팩토링 후

```
대규모 리팩토링 완료:
사용자: "프로젝트 개선 사이클"
↓
실행:
  ✅ 리팩토링으로 인한 버그 발견 및 해결
  ✅ 타입 체크 통과 확인
  ✅ 모든 테스트 통과 확인
  ✅ 문서 동기화
↓
결과:
  리팩토링 안정성 확인
  숨겨진 버그 발견 및 해결
  코드 품질 검증
```

## 실행 시간

```
사이클 1회 예상 시간:
  - audit-to-issues:         5-10분
  - issues-plan-and-resolve: 10-30분 (이슈 수에 따라)
  - docs-audit:              2-5분
  ────────────────────────────────
  Total:                     20-45분/cycle

예상 총 시간:
  - 1회 사이클: 20-45분
  - 3회 사이클: 60-135분
  - 자동화로 인해 실제는 더 짧음
```

## 옵션

### 1. 최대 사이클 수 제한

```
"프로젝트 개선 사이클 (최대 3회)"
```

- 무한 반복 방지
- 리소스 제한 설정
- 예: 매주 최대 3회만 실행

### 2. 특정 영역만 감시

```
"프로젝트 개선 사이클 (보안만)"
"프로젝트 개선 사이클 (타입 체크만)"
```

- 특정 문제만 집중 해결
- 빠른 실행 시간

### 3. 수동 검증 모드

```
"프로젝트 개선 사이클 (수동 승인)"
```

- 각 이슈 해결 전 사용자 승인
- 보수적인 접근
- 자동 해결이 불안할 때 사용

- [ ] 발견된 모든 이슈가 해결되었는가?
- [ ] 문서가 정확히 업데이트되었는가?

## FAQ

### Q: 이슈가 자동으로 해결되지 않으면?

**A**: issues-plan-and-resolve 스킬에서 자동 해결이 불가능한 이슈는 수동으로 처리합니다. 사용자가 이슈를 검토하고 필요한 조치를 취할 수 있습니다.

### Q: 사이클이 언제까지 반복되나?

**A**: audit-to-issues에서 새로운 이슈가 등록되지 않을 때까지 반복됩니다. 이슈가 없으면 사이클이 자동으로 종료됩니다.

### Q: 특정 스킬만 실행하고 싶으면?

**A**: 해당 스킬을 직접 호출하세요:
```
/audit-to-issues
/issues-plan-and-resolve
/docs-audit
```

### Q: 이전 사이클 결과를 보고 싶으면?

**A**: git 커밋 기록을 확인하세요:
```bash
git log --oneline | grep "프로젝트 개선 사이클"
```
